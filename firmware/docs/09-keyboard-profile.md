# 09-keyboard-profile — 연결된 키보드마다 다른 레이아웃과 키맵

**상태: ⬜ 미착수** — 구현 상세는 착수할 때 채운다. 지금은 **검토 결과와 판단 근거**다.

## 목표

USB-A 에 꽂은 키보드를 **알아보고** 그 키보드에 맞는 레이아웃(편집 화면의 그림)과
키맵을 자동으로 쓴다. 여러 키보드의 것을 보드에 담아 둔다.

풀사이즈 배열은 **디폴트로 남긴다.** 설정하지 않아도 항상 동작하는 바닥이 있어야 한다.

## 배경 / 근거

### 레이아웃은 "그림" 이다 — 기능이 아니다

이 보드의 매트릭스 좌표는 HID usage 다 (`row = usage>>4`, `col = usage&0xF`).
키맵 256칸이 전부 채워져 있어서 **어떤 키보드를 꽂든 이미 동작한다.**
안 그린 키도 눌린다 — VIA/Vial 에서 못 고칠 뿐이다 → [06-via.md](06-via.md#4-배열--왜-풀사이즈인가)

그래서 이 단계의 값어치는 두 가지로 갈린다:

| | 무엇 | 값어치 |
|---|---|---|
| 레이아웃 | 편집 화면에 **실제 그 키보드**가 그려진다 | 편집 UX. HHKB 키맵을 풀사이즈 그림 위에서 고치는 건 헷갈린다 |
| **키맵 프로파일** | 키보드마다 **다른 키맵** | **기능이다.** HHKB 와 풀사이즈를 번갈아 쓰면 지금은 키맵 한 벌을 공유한다 |

**체감은 키맵 쪽이 크다.** 레이아웃만 하고 끝내지 않는다.

### ★ VIA 와 Vial 이 갈린다

**Vial 은 키보드 정의를 장치에서 읽어간다.**

```c
/* vial-qmk : quantum/vial.c */
case vial_get_size:  sz = sizeof(keyboard_definition); ...
case vial_get_def:   memcpy_P(msg, &keyboard_definition[start], end - start);
```

구현이 **바이트 범위 읽기**다. `keyboard_definition[]` 배열 대신 플래시에서 읽게
바꾸면 연결된 키보드에 따라 다른 정의를 내줄 수 있다.

**VIA 는 이 통로가 없다.** 앱이 VID/PID 로 *자기 저장소*에서 정의를 찾는다.
장치가 무엇을 갖고 있든 보지 않는다 (`via.c` 의 명령 목록에 정의 서빙이 없다).

| | VIA | Vial |
|---|---|---|
| 웹페이지로 레이아웃 학습·생성 | ✅ | ✅ |
| 보드에 여러 벌 저장·회수 | ✅ | ✅ |
| **그림** 자동 전환 | ❌ 사용자가 Design 탭에 넣는다 | ✅ 자동 |
| **키맵** 자동 전환 | ✅ | ✅ |

키맵 전환은 **보드가 결정**하고 앱은 `dynamic_keymap_get_keycode()` 로 읽어갈 뿐이라
어느 앱이든 똑같이 동작한다. VIA 에서 못 하는 것은 그림 자동 전환 하나다.

### 이미 있는 조각들

| 필요한 것 | 상태 |
|---|---|
| 눌린 키의 usage 읽기 | ✅ `id_switch_matrix_state` (`VIA_INSECURE`, 06단계) |
| 연결 키보드 VID/PID | ✅ `usbh_hid.c` 의 `hid_info[].vid/pid` |
| 플래시 저장 | ✅ `hw/driver/flash.c`. **1.8MB 가 비어 있다** |
| 커스텀 raw HID 명령 통로 | ✅ `via_command_kb()` (bootloader_jump 에 사용 중) |
| 키맵 주소를 옮길 자리 | ✅ `nvm_dynamic_keymap_*()` — 아래 참고 |

## 설계

### 1. 학습은 브라우저 키 이벤트가 아니라 raw HID 로 한다

**★ 브라우저 키 이벤트를 쓰면 안 된다.** OS 가 F13~F24 를 앱에 안 넘기고
(06단계에서 실제로 겪었다), Fn 조합·미디어키도 삼킨다.

`id_switch_matrix_state` 로 매트릭스를 직접 읽으면 **usage 가 그대로 나온다.**
WebHID 로 우리 raw HID 인터페이스(usage page `0xFF60`)를 연다.

**★ 그런데 그 명령은 vial 빌드에서 안 된다.**

vial-qmk 판 `via.c` 에는 offset 페이징이 없고 `(cols/8+1)*rows <= 28` 크기 제한이
있다. 우리는 48 이라 코드가 통째로 빠진다 → [07-vial.md](07-vial.md)

그래서 **우리 커스텀 명령으로 페이징해서 내준다** (`via_command_kb()`, ID `0xA0`~).
양쪽 끝을 다 우리가 만드는데 남의 형식과 싸울 이유가 없다.
via · vial 어느 빌드에서도 같은 방법으로 읽힌다.

### 2. "누르세요" 마법사 + 드래그앤드롭 보정

드래그앤드롭보다 **마법사가 빠르다** — 좌표가 곧 usage 라 누른 걸 그대로 적으면 끝이다.

```
KLE 를 올린다  →  한 자리씩 강조  →  그 키를 누른다  →  usage 기록  →  반복
```

드래그앤드롭은 **못 누르는 키 보정용**으로 남긴다 (Fn 조합처럼 단독으로 안 눌리는 것,
같은 usage 를 두 자리에 두고 싶은 것).

### 3. 키보드 식별 — VID/PID 만으로는 약하다

**저가 키보드들이 같은 VID/PID 를 공유하고 `0000` 도 있다.**
같은 VID/PID 로 ANSI/ISO 변형이 나오기도 한다.

→ **VID + PID + product string 을 해시**해서 키로 쓰고, **수동 선택도 남긴다.**
`tuh_hid_mount_cb` 에서 `tuh_vid_pid_get()` 은 이미 받고 있으므로
product string 만 더 읽으면 된다 (`tuh_descriptor_get_product_string_sync`).

### ★ VIA 의 "정의를 다시 넣어야 하는" 문제 — PID 를 슬롯마다 다르게

**VIA 는 정의를 VID/PID 로 찾는다.** 우리가 어떤 키보드를 꽂든 `0483:5305` 하나라
VIA 안에는 정의가 **한 벌만** 남는다. 키보드를 바꾸면 그 JSON 을 다시 넣어야 하고,
되돌아오면 또 넣어야 한다.

**슬롯마다 PID 를 다르게 보고하면 VIA 가 알아서 고른다.**

```
슬롯 0 -> 0x5305      슬롯 1 -> 0x5306      슬롯 2 -> 0x5307   ...
```

사용자는 키보드마다 정의를 **한 번씩만** Design 탭에 넣어 두면 된다. 그다음부터는
꽂는 대로 VIA 가 맞는 것을 고른다. Vial 과 같은 경험이 된다.

동작 순서:

1. 소스 키보드가 바뀐다 → 저장소에서 슬롯을 찾는다
2. PID 를 `0x5305 + 슬롯` 으로 바꾼다
3. `tud_disconnect()` / `tud_connect()` 로 PC 쪽 재열거 — VIA 가 다른 장치로 본다
4. 저장된 것이 없으면 슬롯 없음 → `0x5305` (풀사이즈 기본)

**대가**

| | |
|---|---|
| PID 16개를 쓴다 | 다른 baram 키보드와 겹치지 않게 `0x5305`~`0x5314` 를 통째로 예약해야 한다 |
| 재열거가 눈에 보인다 | PC 에서 키보드가 잠깐 사라진다. 어차피 소스를 물리적으로 바꾸는 순간이라 견딜 만하다 |
| `flash.py` | 지금은 PID 를 정확히 맞춰 본다. 범위로 바꿔야 한다 |
| 정의 파일 | `productId` 가 슬롯마다 달라야 한다 — 마법사가 채워 준다 |
| 키맵 | 이것만으로는 그림만 바뀐다. **키맵도 바뀌려면 3단계(프로파일)가 필요하다** |

Vial 은 이 장치가 필요 없다 — 정의를 직접 내주므로 PID 는 하나로 둬도 된다.
**PID 전환은 VIA 를 위한 것이다.**

### ★ Vial 의 잠금 — 우리 명령만 연다

Vial 은 매트릭스 읽기를 잠금 뒤로 숨긴다 (raw HID 키로거 방지).
**우리 명령은 잠겨 있어도 답한다.** via 빌드에서 `VIA_INSECURE` 로 이미 열어 둔 것과
같은 문이고, 이 보드는 "어떤 usage 가 오는가" 를 알아야 쓸 수 있기 때문이다.

**★ `VIAL_INSECURE` 로 통째로 푸는 것은 안 된다.**

```c
/* vial-qmk 의 quantum/via.c */
#if defined(VIAL_ENABLE) && !defined(VIAL_INSECURE)
case id_bootloader_jump: {          /* <- VIAL_INSECURE 를 켜면 이 케이스가 사라진다 */
```

부트로더 버튼이 죽는다. 매크로 쓰기와 키맵에 `QK_BOOT` 심기도 같이 열린다.
그쪽은 잠가 둔 채로 두고 **우리 명령 하나만** 연다.

`INFO` 의 잠금 바이트는 그래서 **알림용**이다 — "Vial 의 다른 기능이 잠겨 있는가".

### 4. 온디바이스 저장

플래시 뒤쪽에 blob 저장소를 둔다. 용량 추산 —

| | 크기 |
|---|---|
| 60% 정의 (비압축 JSON) | ~8KB |
| 60% 정의 (LZMA) | ~1KB |
| 16개 키보드분 (비압축 기준) | **128KB** |

`hw_def.h` 의 영역 표에 추가한다. 지금 `0x1F8000` 이후 32KB 만 예약해 뒀지만
펌웨어가 111KB 라 **1.8MB 가 놀고 있다.** 넉넉히 잡으면 된다.

커스텀 raw HID 명령은 `via_command_kb()` 에 붙인다.
**VIA 의 명령 ID 와 겹치지 않게 `0xA0` 부터 쓴다** (VIA 는 `0x14` 근처까지 쓴다).

### 5. Vial 정의 서빙을 플래시로

`vial_get_size` / `vial_get_def` 가 배열 대신 플래시를 읽게 바꾼다.
연결된 키보드에 맞는 blob 을 고르는 것은 우리 코드다.

**LZMA 압축**이 걸린다 — Vial 정의는 압축돼 있다.
브라우저에서 압축하거나 비압축을 허용하도록 손봐야 한다. 착수 시 정한다.

### 6. ★ 키맵 프로파일 — upstream 을 패치하지 않는다

wish-he 는 벤더링한 `dynamic_keymap.c` 를 직접 고쳐 오프셋을 넣었다.
**QMK 0.33 은 NVM 계층이 생겨서 그럴 필요가 없다.**

```
nvm_dynamic_keymap_read_keycode / update_keycode / read_buffer / ...
```

이게 교체 가능한 seam 이다. `quantum/nvm/eeprom/nvm_dynamic_keymap.c` 를 빌드에서
빼고 **우리 것을 넣는다.** 주소 계산에 프로파일 오프셋만 더하면 된다.

```c
// 우리 nvm_dynamic_keymap.c
static uint32_t profileOffset(void)
{
  return (uint32_t)kbdProfileGet() * KEYMAP_BLOCK_SIZE;
}
```

`KEYMAP_BLOCK_SIZE = DYNAMIC_KEYMAP_LAYER_COUNT * MATRIX_ROWS * MATRIX_COLS * 2`
= 8 × 16 × 16 × 2 = **4096B**. 프로파일 4벌이면 16KB — 지금 EEPROM 크기를 넘으므로
**영역을 키워야 한다** (지금 VIA 16KB). 착수 시 배치를 다시 잡는다.

★ 초기화 함정: `dynamic_keymap_reset()` 은 **지금 프로파일 한 벌만** 채운다.
그대로 두면 나머지 프로파일이 전부 `KC_NO` 라 옮기는 순간 키보드가 죽는다.
초기화에서 네 벌을 돌며 다 채워야 한다 (wish-he 가 같은 함정을 겪었다).

### 7. 핫스왑 — 앱은 정의를 한 번만 읽는다

Vial 앱은 연결 시 정의를 한 번 읽는다. USB-A 쪽 키보드를 바꿔 꽂아도 다시 안 읽는다.

→ 소스 키보드가 바뀌면 `tud_disconnect()` / `tud_connect()` 로 **PC 쪽 재열거**를 건다.
되는 수법이지만 PC 에서 키보드가 잠깐 사라진다. 부작용을 재고 결정한다.

### 8. VIA 앱을 포크하는 선택지 — 지금은 하지 않는다

VIA 의 구멍(그림 자동 전환)은 **앱을 포크하면 메워진다.** 라이선스는 GPL-3.0 이라
포크·수정·배포 모두 문제없고, 이미 `~/hdd/git/via-he` 로 해 본 방식이다.

그래도 지금은 하지 않는다.

| | 포크 없이 | VIA 포크 |
|---|---|---|
| Vial 그림 자동 전환 | ✅ | — (Vial 은 원래 된다) |
| VIA 그림 자동 전환 | ❌ 수동 | ✅ |
| 유지 비용 | 0 | upstream 추적 |
| 사용자 | usevia.app 그대로 | 우리 앱을 써야 한다 |

**VIA 포크는 "Vial 이 이미 주는 것" 을 VIA 에서도 되게 하려고 내는 비용**이다.
09단계 1단계에 필요한 것은 WebHID + KLE + 마법사뿐이라 **작은 독립 페이지로 충분하다.**
VIA 전체를 끌고 다닐 이유가 없다.

**★ 포크한다면 이 저장소에 복사하지 않는다.**

- 크기 — `via-he` 가 596MB(node_modules 포함), 소스만 36MB.
  우리는 QMK/Vial 도 서브모듈 대신 fetch 로 받아 저장소 증가를 0 으로 유지했다.
  같은 논리가 그대로 적용된다 → [00-context.md](00-context.md#하지-않기로-한-것)
- 갱신 — 벤더링하면 upstream 갱신이 수동 diff 가 된다. QMK 벤더링을 거부한 이유와 같다
- 툴체인 — 펌웨어 저장소에 node/bun 빌드가 섞인다

별도 저장소로 두고 `upstream.json` 에 리비전만 고정하는 쪽이 지금까지의 관례와 맞는다.
나중에 정말 필요해지면 **`via-he` 에 얹는 것**도 방법이다 — 포크를 하나만 유지하면 된다.

#### 펌웨어에 더한 것 — 명령 하나

```
0xA0 0x00 INFO     버전 / 매트릭스 크기 / 꽂힌 키보드 vid:pid
0xA0 0x01 PRESSED  지금 눌린 usage 목록
```

**★ upstream 훅에 기대지 않는다.**
`via_command_kb()` 는 qmk_firmware 에만, `raw_hid_receive_kb()` 는 vial-qmk 에만 있다.
어느 쪽에 붙여도 반대편에서 죽은 코드가 된다 — 07단계에서 실제로 겪었다
(링커가 조용히 버려서 빌드 크기가 안 변했다).
우리가 이미 raw HID 큐를 직접 비우고 있으므로 `qmkUpdate()` 에서 먼저 걷어낸다.

**비트맵이 아니라 눌린 usage 목록을 보낸다.** Vial 의 매트릭스 조회가 막혔던 이유가
32바이트 리포트에 16x16 이 안 들어가서인데, 목록이면 최대 14개라 넉넉하다.

vial 빌드에서는 Vial 의 잠금 정책을 따른다 (`vial_unlocked`).

#### ★ 같은 raw HID 를 셋이 나눠 쓴다

마법사를 열어 둔 채 VIA 를 열면 **VIA 가 장치를 못 알아본다.**

```
Command Name: GET_PROTOCOL_VERSION
Response: 160 1 0 0 0 ...          <- 160 = 0xA0. 마법사의 PRESSED 응답이다
Received invalid protocol version from device
```

VIA 가 보낸 질문의 답을 마법사가 가로챈 것이다. **장치는 멀쩡하다** —
VIA 명령에 전부 정상 응답하는 것을 따로 확인했다.

해결: 탭이 가려지면 폴링을 멈추고(`visibilitychange`), **[연결 끊기]** 버튼을 뒀다.

#### 프리셋은 손으로 그리지 않는다

QMK 의 **레이아웃 좌표** 와 그 레이아웃을 쓰는 **키보드의 기본 키맵**을 짝지어 뽑는다
(`web/tools/gen_presets.py`). 1U 폭 하나만 틀려도 마법사가 엉뚱한 자리를 가리킨다.

**★ 좌표와 키맵은 같은 매크로에서 와야 한다.** 처음에 커뮤니티 레이아웃 좌표에
"그 레이아웃을 쓴다고 적힌" 키보드의 키맵을 붙였는데 그 키보드의 `LAYOUT` 은 다른
매크로였다. 키가 하나 더 많아 **범례가 두 번째 행부터 한 칸씩 밀렸다.**
지금은 매크로 이름이 같고 **토큰 수 == 자리 수** 인 짝만 고른다.

### 2단계 — 온디바이스 저장 + 자동 전환

- [ ] `hw_def.h` 에 blob 저장 영역
- [ ] blob 저장소 (목록 / 읽기 / 쓰기 / 삭제)
- [ ] 커스텀 raw HID 명령 (`0xA0`~)
- [ ] 키보드 식별 — VID/PID/product string 해시
- [ ] Vial `vial_get_size` / `vial_get_def` 를 플래시에서 서빙
- [ ] 웹페이지에서 보드로 업로드 / 회수

### 3단계 — 키보드별 키맵 프로파일

- [ ] EEPROM 영역 재배치 (프로파일 N벌)
- [ ] 우리 `nvm_dynamic_keymap.c` (프로파일 오프셋)
- [ ] 초기화에서 전 프로파일 채우기
- [ ] 연결 키보드 → 프로파일 선택
- [ ] VIA 커스텀 메뉴에 수동 선택 / 현재 프로파일 표시

## 완료 판정

1. 웹페이지에서 KLE 를 올리고 키를 눌러 레이아웃을 만든다
2. 만든 정의를 VIA Design 탭 / Vial 에서 쓸 수 있다
3. 보드에 두 대 이상의 키보드 레이아웃을 저장한다
4. 키보드를 바꿔 꽂으면 **Vial 이 그 키보드를 그린다**
5. 키보드를 바꿔 꽂으면 **키맵이 따라 바뀐다 (VIA·Vial 둘 다)**
6. 저장한 적 없는 키보드를 꽂으면 **풀사이즈 디폴트로 동작한다**

## 열린 질문

| 항목 | 내용 |
|---|---|
| LZMA | Vial 정의는 압축돼 있다. 브라우저에서 압축할지, 비압축을 허용하도록 고칠지 |
| VID/PID 충돌 | 해시에 product string 을 넣어도 겹칠 수 있다. 수동 선택 UI 가 필요하다 |
| 핫스왑 재열거 | `tud_disconnect/connect` 의 부작용 (PC 에서 키보드가 잠깐 사라진다). 옵션으로 둘지 |
| EEPROM 배치 | 프로파일 N벌이면 지금 16KB 로는 부족하다. wear leveling 항목과 같이 다시 잡는다 → [roadmap](roadmap.md#마감08-이후에-할-것) |
| 웹앱 배포 | GitHub Pages. WebHID 는 Chrome 계열만 된다 (Safari·Firefox 미지원) |
