## 핀 배정 근거

PDF 의 텍스트를 좌표와 함께 추출해서 넷 연결을 검증했다. 눈으로 본 게 아니다.

### WS2812 = GPIO16

RGB 블록에서 `WS2812B-0807`(L1)의 `DIN` 핀(x=442.2, y=513.8) 바로 옆에
`GPIO16` 넷라벨(x=467.8, y=516.9)이 붙어 있다. 이 블록의 유일한 GPIO 다.

### WS2812 전송 순서는 R,G,B (표준과 다름)

표준 WS2812B 는 **G,R,B** 순으로 받는다. 그런데 이 보드의 WS2812B-0807 은 **R,G,B** 다.

**실기에서 확인했다.** 논리적으로 초록(`r=0, g=16, b=0`)을 보냈는데 빨강이 켜졌다 →
첫 바이트가 R 로 해석된다 → `R,G,B`.

hola-mini 의 `ws2812.h` 는 `ws_pixel_t = {b, r, g, w}` 유니온에 G,R,B 순서를 그대로 박아
두었지만, 여기서는 순서를 `hw_def.h` 의 `HW_WS2812_ORDER_RGB` 로 빼고
`ws2812Refresh()` 가 변환하게 고쳤다. 부품이 바뀌면 이 매크로만 손대면 된다.

### USB-A D+ = GPIO12, D− = GPIO13

J1 패드와 넷라벨의 y 좌표가 일정한 간격으로 대응한다.

| J1 패드 | y | 핀 이름 | 넷라벨 (x=587.3) | 직렬 저항 | GPIO 넷라벨 (x=536.6) |
|---|---|---|---|---|---|
| PIJ101 | 287.9 | VBUS | VSYS (278.1) | — | — |
| PIJ102 | 281.9 | DATA− | `DB_N` (272.1) | R11 27R | **`GPIO13`** (272.1) |
| PIJ103 | 275.6 | DATA+ | `DB_P` (266.0) | R12 27R | **`GPIO12`** (266.0) |
| PIJ104 | 269.6 | GND | GND (260.0) | — | — |

넷라벨 텍스트는 배선보다 일정하게 9.8 아래에 찍히고, 그 오프셋이 네 줄 모두 같다.
`DB_N` / `GPIO13` 이 같은 y(272.1), `DB_P` / `GPIO12` 가 같은 y(266.0) 라서
**같은 배선에 두 이름이 붙어 있다** — `DB_N` 은 지역명, `GPIO12/13` 이 전역명이다.

**D+ = 12, D− = 13 이라 `DM = DP + 1`** 이고, 이건 Pico-PIO-USB 의 요구사항을 그대로 만족한다.
보드가 처음부터 PIO USB host 를 염두에 두고 설계된 것으로 보인다.

> `GPIO0` / `GPIO1` 넷라벨(x=413.8, y=278.1/272.1)은 U3 의 2번·3번 핀 배선에 붙은
> **MCU 쪽 라벨일 뿐 USB 와 무관하다.** 이 좌표 검증 전에는 여기로 오해하기 쉽다.

### Type-C = 네이티브 USB

U3 의 `USB_DP`(52번, y=293.0) → R3 27R → `D_P`,
`USB_DM`(51번, y=286.9) → R4 27R → `D_N` 이 Type-C 커넥터로 간다.

## 확인이 필요한 항목

### R10 / R13 — USB-A 포트의 풀업 (해결됨)

| 저항 | 실크 값 | 연결 | 실장 여부 | 판정 |
|---|---|---|---|---|
| R10 | NC / 1.5K | 3V3 → `DB_N` (D−, GPIO13) | **미실장** | OK |
| R13 | 1.5K | 3V3 → `DB_P` (D+, GPIO12) | 실장되어 있었음 | ✅ **제거 완료** |

둘 다 **USB device 쪽 풀업**이다. D+ 에 1.5K 풀업이 있으면 "full-speed device 가 연결됨"을 뜻한다.

이 포트는 **PIO-USB 호스트**로 쓴다. 호스트 쪽은 15K 풀다운이 필요하고
Pico-PIO-USB 가 그걸 내부 풀다운으로 처리한다.
**D+ 에 1.5K 풀업이 살아 있으면 아무것도 안 꽂아도 장치가 연결된 것으로 보여
호스트 스택이 계속 열거를 시도하다 타임아웃한다.**

#### 어떻게 확인했나 / 검증했나

GPIO12 / GPIO13 을 입력 + **내부 풀다운**(RP2350 기준 약 50~80kΩ) 으로 두고 읽었다.
외부 1.5K 풀업이 있으면 내부 풀다운을 이겨서 HIGH 가 된다.

USB-A 에 **아무것도 꽂지 않은 상태**에서:

| 상태 | GPIO12 (D+) | GPIO13 (D−) | 색 | 판정 |
|---|---|---|---|---|
| R13 제거 전, USB-A 비어 있음 | **HIGH** | LOW | 🔴 | R13 실장 / R10 미실장 |
| R13 제거 후, USB-A 비어 있음 | LOW | LOW | 🟢 | **제거 확인** |
| R13 제거 후, FS 키보드 연결 | **HIGH** | LOW | 🔴 | **`GPIO12 = D+` 확증** |

진단 펌웨어는 [03-usb-host.md](03-usb-host.md#부록--usb-a-풀업-진단-펌웨어) 에 남겨 두었다.

> **부수 효과 — 핀 배정 확증**
> 제거 후 빈 포트에서는 양쪽 LOW, FS 키보드를 꽂으면 D+ 만 HIGH 가 됐다.
> 회로도 좌표 분석에서 읽은 `GPIO12 = D+`, `GPIO13 = D−` 가 실측으로 확정되었다.

#### 제거하지 않고 쓸 수 있나 — 권하지 않는다

**신호 자체는 안 깨진다.** 1.5K 풀업은 원래 USB 장치가 갖는 부하이고 호스트는 평소에도
그걸 상대로 드라이브한다. 키보드를 꽂으면 1.5K 가 병렬로 750Ω 이 되어 드라이브 전류가
약 4.4mA 로 늘지만 RP2350 GPIO 가 감당한다.

깨지는 건 **버스 상태 판별** 세 가지다.

| | 문제 | 우회 가능? |
|---|---|---|
| 연결 감지 | 아무것도 안 꽂아도 항상 "FS 장치 연결됨" | 가능 — 항상 연결로 간주 |
| 분리 감지 | 빼도 D+ 가 HIGH 라 SE0 가 안 잡힌다 | 부분적 — 트랜잭션 N회 연속 실패를 분리로 |
| **속도 판별** | LS 장치는 D− 에 풀업이다. D+ 가 항상 HIGH 면 **둘 다 HIGH** = 정의되지 않은 상태 | **불가** |

앞의 둘은 Pico-PIO-USB / TinyUSB 의 연결 감지 로직을 패치하면 어느 정도 덮을 수 있다.
핫플러그는 불안정해진다.

**결정적인 건 세 번째다. Low-speed 키보드를 못 쓴다.**
속도 판별이 라인 풀업 위치로만 이뤄지는데 그게 망가진다.
저렴하거나 오래된 USB 키보드 중 LS 가 꽤 많고,
"아무 키보드나 꽂으면 되는 변환기" 라는 이 프로젝트 목표와 정면으로 충돌한다.

전압 분압을 재서 구분하는 방법도 막혀 있다 — GPIO12 는 ADC 핀이 아니고
(RP2350A 는 GPIO26~29 만), 내부 풀다운은 50~80kΩ 이라 1.5K 를 이길 수 없다.

##### 예외 — 키보드를 먼저 꽂고 부팅하면

"항상 연결됨으로 보인다" 는 문제는 **실제로 연결돼 있으면 문제가 아니다.**
FS 키보드를 먼저 꽂아 두고 보드를 PC 에 연결하면:

- D+ 는 장치의 1.5K 와 R13 이 병렬로 750Ω → D+ high / D− low → **FS 로 올바르게 판별**
- 신호도 750Ω 을 상대로 드라이브하면 되므로 문제없다
- **열거가 정상적으로 된다**

즉 **FS 키보드 하나를 고정으로 쓰는 용도라면 R13 을 두고도 쓸 수 있다.**
인두가 없을 때의 대안이다. 단 아래는 그대로 남는다.

| | |
|---|---|
| LS 키보드 | 꽂는 순서와 무관하게 불가 |
| 분리 감지 | 한 번 꽂은 뒤 빼면 모른다. 키보드를 바꾸려면 **보드를 재부팅**해야 한다 |
| 부팅 레이스 | 원래 풀업은 "장치 준비됨" 신호이기도 하다. R13 이 그걸 미리 올려서, 키보드 MCU 가 부팅하기 전에 호스트가 열거를 시작할 수 있다. 첫 시도가 실패하고 재시도 로직에 기대게 된다 |

**칩저항 하나 떼는 것 대비 얻는 게 없다.**

#### 조치

R13 을 제거한다. USB-A 커넥터와 27R(R11/R12) 사이, R10 바로 아래의 1.5K 칩저항이다.
제거 후 진단 펌웨어가 **초록**으로 바뀌면 해결이다.

**이 보드는 R13 을 제거했다.**

제거하지 않은 보드로 3단계를 진행해야 한다면, 위 "예외" 대로
**FS 키보드를 먼저 꽂고 부팅하는 방식**으로 검증할 수 있다.

### J1 VBUS

J1 의 VBUS 는 VSYS 직결이다. 전원 스위칭이 없으므로
부팅 시 호스트 포트에 전원이 언제 올라오는지는 3단계에서 실측한다.
