# test — 호스트에서 도는 시뮬레이션

보드 없이 확인할 수 있는 것을 여기서 확인한다.

```bash
cd firmware/qmk-link/test
make                      # 지금 소스로 돌린다
make rev REV=269f452      # 그 커밋의 소스로 돌린다 (회귀 재현)
make clean
```

## 왜 시뮬레이션인가

이 보드의 고장 중에는 **실기로 재현하기 번거로운 것**이 있다.
매크로 · 탭댄스 리포트 유실([이슈 001](../../docs/issues/001-vial-app-macro-tapdance.md))이 그랬다 —
Vial 앱으로 매크로를 짜고, USB-A 키보드의 그 키를 손으로 누르고, PC 가 뭘 받았는지
따로 봐야 확인이 된다. CLI 에는 매트릭스에 키를 넣어 주는 명령이 없다.

리포트 큐 자체는 시간과 엔드포인트만 있으면 되는 순수한 로직이라
호스트에서 그대로 돌릴 수 있다.

## ★ 펌웨어 소스를 그대로 컴파일한다

베껴 온 사본이 아니다. `../src/hw/driver/usb/usbd_hid.c` 를 직접 컴파일한다.
사본을 두면 반드시 갈라지고, 갈라진 사본을 통과시켜 봐야 아무 의미가 없다.

흉내내는 것은 둘뿐이고 `stub/` 에 있다.

| | 흉내내는 것 |
|---|---|
| `stub/tusb.h` | `tud_hid_n_ready` · `tud_hid_n_report` · `tud_task` · `tud_mounted` |
| `stub/bsp.h` | `millis()` |

시간 모델은 실제 값을 쓴다 — 엔드포인트는 **1ms 마다 하나씩** 가져가고
(`EP_KBD_INTERVAL`), `tud_task()` 한 번은 50us 다.

## hid_queue_sim — HID 리포트 큐

매크로 · 탭댄스는 **한 번의 `keyboard_task()` 안에서** 리포트를 연달아 보낸다
(`TAP_CODE_DELAY` 기본 0). 그 사이에 메인 루프가 안 돌므로 엔드포인트는 계속 busy 다.
그 상황을 그대로 재생하고 **PC 가 실제로 받은 열**을 보낸 열과 비교한다.

| 시나리오 | 무엇을 잡나 |
|---|---|
| 1. 매크로 `Ctrl+Space` | 보류함 덮어쓰기 — 사용자 보고 3번 |
| 2. 매크로 반복 키 `aa` | 섀도를 "마지막으로 나간 것" 과 비교하던 것 |
| 3. 탭댄스 `LCA(KC_H)` 탭 | 사용자 보고 2번 |
| 4. 긴 매크로 40자 (80 리포트) | 큐 16칸을 넘길 때 |
| 5. 호스트가 멈춘 동안 80 리포트 | 넘쳐도 **최종 상태**는 나가는가 (키 고착) |

`make rev REV=269f452` 로 수정 전 소스에 돌리면 1~4 가 실패한다.
탭댄스는 PC 가 `[Ctrl+Alt][빈]` 만 받는다 — **H 가 한 번도 안 나간다.**
보고된 증상 그대로다.

## 보드 위에서 하는 쪽 — `key sim`

이 시뮬레이션이 보는 것은 **큐**다. 그 위에 있는 QMK(매크로 · 탭댄스 · 레이어)가
무슨 리포트를 만들어 내는지는 보드에서만 알 수 있다. 그쪽은 CLI 에 있다.

```
key sim tap <usage> [hold_ms]     가상 키 하나를 눌렀다 뗀다
key sim report <8바이트> [..]     mods 포함 boot 리포트를 그대로
```

**호스트로는 안 내보낸다. 기록만 한다.** 주입한 키는 진짜 키와 구별이 안 되므로
그대로 PC 에 입력된다 — 시험을 걸어 놓고 손을 떼면 지금 열려 있는 아무 창에나
쏟아진다. 그래서 플래그를 두지 않고 **명령 하나가 곧 실험 하나**이고 끝나면
스스로 원복한다.

```
cli# key sim report 0x01 0 0x2C
  #   시각  단계 IF   리포트
  0   +0      요청 IF0  mods 00  keys 2C ...
  1   +1      요청 IF0  mods 01  keys 2C ...
  2   +50     요청 IF0  mods 01  keys 00 ...
  3   +50     요청 IF0  mods 00  keys 00 ...
```

`#2` 와 `#3` 이 **같은 +50ms** 다 — 한 번의 `keyboard_task()` 안에서 두 리포트가
나간다. 이슈 001 이 깨지던 바로 그 조건이고, 실기에서 이렇게 확인한다.

| | 무엇을 보나 |
|---|---|
| `test/` (여기) | 큐. 실제 타이밍으로, 옛 소스와 비교까지 |
| `key sim` (보드) | QMK 가 만드는 리포트 열. 큐는 안 거친다 |

## 새 테스트를 더할 때

- `TESTS` 에 이름을 더하고 같은 패턴으로 규칙을 하나 쓴다
- **stub 을 늘리는 것은 신중히.** 흉내낼 게 많아진다는 건 그 코드가
  hw 에 너무 붙어 있다는 뜻이다. 그럴 땐 코드를 가르는 쪽이 맞다
