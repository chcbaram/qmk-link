# qmk-link 배열 마법사

KLE 로 그린 배열의 각 자리에 **그 키가 실제로 보내는 HID usage** 를 채워
`layout-via.json` / `layout-vial.json` / `layout-kle.json` 을 만든다.

## 왜 브라우저 키 이벤트를 안 쓰나

OS 가 F13~F24 를 앱에 안 넘기고 Fn 조합·미디어키도 삼킨다.
대신 **보드에서 직접 읽는다** — WebHID 로 raw HID(`0xFF60`) 를 열고
qmk-link 고유 명령(`0xA0`)으로 눌린 usage 를 받는다.

## 띄우는 법

**WebHID 는 보안 컨텍스트에서만 된다.** `file://` 로 열면 동작하지 않는다.

```bash
cd web
python3 -m http.server 8000
```

→ <http://localhost:8000> (Chrome / Edge. Safari · Firefox 는 WebHID 미지원)

## ★ 펌웨어와 이 페이지는 짝이 맞아야 한다

새 기능은 대개 **양쪽을 같이** 고친다. 한쪽만 갱신하면 그 기능이 조용히 안 돈다 —
실제로 "키보드 이름이 왜 안 뜨지" 로 한참 헤맸는데 보드에 옛 펌웨어가 올라가
있었다.

그래서 연결하면 상태 줄에 늘 적는다:

```
VIAL 펌웨어 V260823R3 (명령 v5) — 매트릭스 16x16, 꽂힌 키보드 1대 (04FE:0006)
```

`명령 v5` 가 이 페이지가 기대하는 것보다 낮으면 **빨간 줄로 "오래됐다"** 고
말해 준다. 그러면 다시 구우면 된다.

거꾸로 페이지가 옛것일 수도 있다 (브라우저 캐시). 프리셋 목록이나 버튼이
설명과 다르면 **강제 새로 고침**한다 (macOS ⌘⇧R).

## ★ VIA / Vial 을 쓰기 전에 [연결 끊기]

**같은 raw HID 인터페이스를 셋이 나눠 쓴다.** 이 페이지가 물고 폴링하는 동안
VIA 를 열면, VIA 가 보낸 질문의 답을 이 페이지가 가로챈다. VIA 에는 이렇게 보인다:

```
Command Name: GET_PROTOCOL_VERSION
Response: 160 1 0 0 0 ...          <- 160 = 0xA0. 우리 명령의 응답이다
Received invalid protocol version from device
```

그래서 VIA 는 "VIA 키보드처럼 응답하지 않는다" 고 판단한다. **장치는 멀쩡하다.**

탭을 옮기면 폴링이 자동으로 멈추지만, 확실하게 하려면 **[연결 끊기]** 를 누른다.

## 화면 순서 = 하는 일의 순서

```
① 보드 연결
② 보드에 담긴 레이아웃    ← 키보드 → SLOT 트리. 여기가 출발점이다
                          키보드 이름은 USB product string 을 읽어 보여 준다
③ 배열 넣기 + 마법사
④ 배열 그림 / 눌린 키 / 직접 넣기
⑤ 보드에 저장
⑥ 파일로 내보내기
```

②가 맨 위인 이유는, 꽂은 키보드가 **이미 담겨 있는지**를 먼저 알아야
"새로 만들지 / 있는 걸 고칠지" 가 정해지기 때문이다.

## 세 가지 흐름

### 처음 만든다

1. **[보드 연결]** — USB-A 쪽에도 배우려는 키보드를 꽂아 둔다
2. ② 에 그 키보드가 `담긴 것이 없다` 로 뜬다 → **[SLOT 추가]**
3. 배열을 넣는다 — **프리셋** / **KLE json 파일 열기** / KLE **Raw data** 붙여넣기
   - 프리셋: HHKB Lite 2 · F1-40 722 · BARAM 45K · 60% ANSI/HHKB · 65% · 75% · TKL · 풀사이즈
4. **[배열 읽기]** → **[마법사 시작]** → 강조된 자리의 키를 누른다
5. 못 누르는 키는 자리를 클릭하고 이름으로 직접 넣는다 (몇 자만 쳐도 목록이 뜬다)
   - 잘못 배웠으면 그 자리를 클릭하고 **[지우기]**, 처음부터 다시면 **[전체 지우기]**
     — 배열은 그대로 두고 배운 키만 비운다
6. **[SLOT n 에 저장]** — 그 SLOT 에 저장한다

### 담아 둔 것을 편집한다

1. **[보드 연결]** → ② 트리에서 그 SLOT 의 **[편집]**
2. 배열과 **배운 키까지 그대로** 올라온다 (범례가 좌표라 되살아난다)
3. 몇 자리 고치고 **[SLOT n 에 덮어쓰기]**

### 변형본을 하나 더 만든다

1. ② 트리의 **[SLOT 추가]** — 빈 자리가 잡힌다 (아직 보드는 안 건드린다)
2. ③ 에서 배열을 넣고 키를 배운다
3. **[SLOT n 에 저장]**

★ **자리를 먼저 만들고 채운다.** 예전에는 `[SLOT n 에 새로 담기]` 가 바로
저장을 시도했는데, 그 시점엔 아직 배운 것이 없어서 조용히 아무 일도 안 하고
아래 담기 칸은 여전히 옛 SLOT 을 가리켰다. 무엇을 만드는 중인지 화면 어디에도
없었다.

### 변형본 사이를 오간다

② 트리에서 쓰고 싶은 SLOT 의 **라디오를 고른다.** 그게 곧 적용이다 —
"지금 적용 중" 을 보여 주는 자리와 "바꾸는 자리" 가 같아서 따로 설명할 것이 없다.

꽂혀 있지 않은 키보드의 줄은 회색이다. 보드는 지금 꽂힌 키보드에 대해서만
적용을 바꿀 수 있다.

**추가 스크립트가 필요 없다.** 이 페이지와 펌웨어만으로 끝난다.

## ★ 저장 SLOT — VIA 가 정의를 VID/PID 로 찾기 때문이다

보드는 꽂힌 키보드의 레이아웃이 몇 번 SLOT 에 담겨 있는지에 따라
PID 를 **`0x5400` + SLOT** 으로 바꿔 보고한다. 담아 둔 것이 없으면 `0x5305` 다.

- **Vial** — 정의를 장치에서 직접 읽어간다. 담기만 하면 바로 그 배열이 뜬다
- **VIA** — 정의를 VID/PID 로 찾는다. 내려받은 `layout-via.json` 을 Design 탭에
  **한 번만** 넣어 두면, 그다음부터는 꽂는 대로 VIA 가 알아서 고른다

내려받는 JSON 의 `productId` 는 고른 SLOT 에 맞춰 자동으로 채워진다.
어긋나면 VIA 가 "모르는 키보드" 로 본다 — 눈에 안 띄는 종류의 오류다.

담긴 것은 두 펌웨어 모두 같은 형식이다. **VIA 펌웨어는 내용을 쓰지 않고
머리말의 vid/pid 만 본다** (그게 SLOT 을 고르는 열쇠다).
Vial 펌웨어는 그 내용을 그대로 Vial 앱에 내준다.

### 언제 연결이 끊기나 — 쓰는 동안은 안 끊긴다

담고 · 고치고 · 적용하는 **내내 연결이 유지된다.**

적용되는 SLOT 이 바뀌면 보드의 PID 도 바뀌어야 하는데(VIA 가 정의를 VID/PID 로
찾는다), 보드는 그 재열거를 **예약만 해 두고 우리가 말을 거는 동안 계속 미룬다.**
실제로 끊기는 것은 **[연결 끊기]** 를 누르거나 탭을 옮겨 조용해진 뒤다 —
그때 VIA / Vial 로 가니 오히려 딱 맞다.

> 보드가 알아서 재부팅하는 방식은 쓰지 않는다. 부팅하면 아직 어느 키보드인지
> 모르는 채로 올라와서 **열거가 두 번**이 되고, EEPROM 의 미저장분이 날아갈 수
> 있다. 브라우저가 새 PID 를 다른 장치로 보는 것도 그대로다.

끊긴 뒤에는 브라우저가 **PID 가 다르면 다른 장치**로 본다. 전에 허락한 적 있는
PID 면 조용히 다시 잡히고, 처음 보는 PID 면 **[보드 연결]** 을 한 번 더 눌러야
한다. 브라우저 규칙이라 우회할 수 없다.

## ★ LZMA 없이 LZMA 를 만든다

Vial 은 정의를 **압축된 채로** 읽어가는데 브라우저에는 LZMA 인코더가 없다
(`CompressionStream` 은 deflate/gzip 뿐이다). 인코더를 벤더링하는 대신
**압축을 안 했다** — `.xz` 는 "압축 안 한 LZMA2 청크" 를 규격으로 허용한다.

| 풀사이즈 153키 정의 | |
|---|---|
| minify 원본 | 1,486 B |
| **무압축 xz** (`xz.js`) | **1,548 B** |
| 파이썬 LZMA | 556 B |
| SLOT 한 칸 | **8,144 B** |

압축률을 통째로 포기해도 세 배 가까이 남는다.
`tools/kbd_upload.py` 도 **같은 무압축 형식**으로 담는다. 형식이 갈리면 그 도구로
담은 SLOT 을 이 페이지가 못 연다.

## 파일

| | |
|---|---|
| `usage-table.js` | **생성물.** `firmware/qmk-link/tools/gen_keymap.py` 의 표에서 뽑는다 |
| `presets.js` | **생성물.** `tools/gen_presets.py` 가 만든다 |
| `app.js` | WebHID · KLE 파싱 · 마법사 · SLOT 트리 · 담기/편집/적용/지우기 · 내보내기 |
| `xz.js` | 압축하지 않는 `.xz` 를 만든다. **블록 헤더 크기 바이트는 `실제크기/4 - 1`** |

**생성물을 손으로 고치지 않는다.** 두 벌을 관리하면 반드시 어긋난다.

### 프리셋은 어디서 오나

QMK / vial-qmk 의 **레이아웃 좌표** 와, 그 레이아웃을 쓰는 **키보드의 기본 키맵**을
짝지어 뽑는다. 좌표는 정확하고 범례는 그 키보드가 실제로 쓰는 이름이다.

```bash
python3 tools/gen_presets.py > presets.js      # vial-qmk 경로가 필요하다
```

손으로 그리면 1U 폭 하나만 틀려도 마법사가 엉뚱한 자리를 가리킨다.

★ QMK 의 layout 배열 순서 = `LAYOUT()` 매크로의 인자 순서라 **순서대로 zip** 하면
맞는다. 행 단위 줄바꿈과는 무관하다 — HHKB Lite 2 는 키맵 4번째 줄이 12개인데
그 행의 자리는 13개다 (오른쪽 Shift 옆 `Fn`). 행으로 맞추려 하면 어긋난다.

★ **좌표와 키맵은 같은 매크로에서 와야 한다.**

처음에 `layouts/default/<이름>/info.json` 의 좌표에다 "그 레이아웃을 쓴다고 적힌
키보드"의 기본 키맵을 붙였는데, 그 키보드의 `LAYOUT` 은 다른 매크로였다.
키가 하나 더 많아서 **범례가 두 번째 행부터 한 칸씩 밀렸다** —
1.5U Tab 자리가 비고 TAB 이 옆칸으로 갔다. 눈으로 봐야 알아채는 오류다.

그래서 지금은 세 조건을 다 만족하는 짝만 고른다:

- `keyboard.json` 에 `LAYOUT_<이름>` 이 있고
- 기본 키맵이 **그 매크로를 그대로 부르고**
- **토큰 수 == 자리 수**

마지막 검사가 이 오류를 자동으로 잡는다.

### ★ 폭(w)이 빠진 정의를 걸러낸다

ortho 배열은 키가 **붙어 있어야 한다**. 그런데 2U 스페이스를 `w` 없이 적고
다음 키를 한 칸 건너뛴 자리에 놓은 정의가 흔하다 (`contra` 의 `planck_mit`,
`wish45_lp`, baram 저장소의 `info.json`). 그대로 그리면 스페이스가 1U 로 나오고
옆이 뻥 뚫린다.

`has_gap()` 이 그런 정의를 버린다 — 단, **TKL · 65% · 풀사이즈는 클러스터
사이가 실제로 떨어져 있으므로** 이 검사는 `ORTHO` 에 든 것에만 건다.

★ `ORTHO` 는 지금 비어 있다. ortho 프리셋을 뺐기 때문이지 검사가 필요 없어서가
아니다. `planck_mit` · `ortho_4x12` 같은 것을 다시 넣으면 **반드시 거기 적는다.**

조건을 통과한 후보가 여럿이면 **범례가 가장 많이 채워지는 것**을 고른다.
같은 점수면 경로 순 — 돌릴 때마다 결과가 바뀌면 안 된다.

### 40% 는 어디서 왔나

| | 출처 |
|---|---|
| `F1-40 722` | vial-qmk 의 `keyboards/baram/geon/f1_40/staggered` |
| `BARAM 45K` | `baram-qmk-8k` 의 **VIA 정의** `.../baram/45k/json/*.JSON` |

★ 45K 는 `keyboard.json` 이 아니라 **VIA 정의**를 쓴다. `keyboard.json` 은
아랫줄이 `x=0,1,2,5,8,9,10,11` 로 **폭(w)이 빠진** 매트릭스 표라 스페이스가 1U 로
나오고 옆이 뚫린다. VIA 정의에는 폭이 제대로 있다 — VIA 가 실제로 그걸로 그리기
때문이다.

★ 그 대신 **VIA 정의의 범례는 그 키보드의 매트릭스 좌표**(`"3,6"`)라 키 이름이
아니다. 행렬형 `keymap.c` 를 읽어 이름으로 바꾼다 (`build_via()`).
같은 이유로 마법사도 남의 VIA 정의를 열 때는 좌표를 usage 로 믿지 않는다 —
`matrix` 가 16x16 일 때만 믿는다.

## 배포

**별도 브랜치를 두지 않는다.** 소스는 `main` 의 `web/` 하나뿐이고,
`.github/workflows/pages.yml` 이 그것만 떼어 Pages 로 올린다.
`web/` 을 고쳐 push 하면 자동으로 배포된다.

저장소 설정에서 한 번만 바꾸면 된다 —
**Settings → Pages → Source: `GitHub Actions`**

그러면 <https://chcbaram.github.io/qmk-link/> 로 열린다.
`file://` 로는 WebHID 가 안 되므로 이 경로가 있어야 남에게 줄 수 있다.

> 처음에는 `gh-pages` 브랜치에 `git subtree push` 하는 방식이었는데,
> 고칠 때마다 손으로 밀어야 해서 잊기 쉬웠다. 그래서 그만뒀다.
