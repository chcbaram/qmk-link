# qmk-link 배열 마법사

KLE 로 그린 배열의 각 자리에 **그 키가 실제로 보내는 HID usage** 를 채워
`layout-via.json` / `layout-vial.json` / `layout-kle.json` 을 만든다.

## 왜 브라우저 키 이벤트를 안 쓰나

OS 가 F13~F24 를 앱에 안 넘기고 Fn 조합·미디어키도 삼킨다.
대신 **보드에서 직접 읽는다** — WebHID 로 raw HID(`0xFF60`) 를 열고
qmk-link 고유 명령(`0xA0`)으로 눌린 usage 를 받는다.

## 띄우는 법

**WebHID 는 보안 컨텍스트에서만 된다.** `file://` 로 열면 동작하지 않는다.

```bash
cd web
python3 -m http.server 8000
```

→ <http://localhost:8000> (Chrome / Edge. Safari · Firefox 는 WebHID 미지원)

## ★ VIA / Vial 을 쓰기 전에 [연결 끊기]

**같은 raw HID 인터페이스를 셋이 나눠 쓴다.** 이 페이지가 물고 폴링하는 동안
VIA 를 열면, VIA 가 보낸 질문의 답을 이 페이지가 가로챈다. VIA 에는 이렇게 보인다:

```
Command Name: GET_PROTOCOL_VERSION
Response: 160 1 0 0 0 ...          <- 160 = 0xA0. 우리 명령의 응답이다
Received invalid protocol version from device
```

그래서 VIA 는 "VIA 키보드처럼 응답하지 않는다" 고 판단한다. **장치는 멀쩡하다.**

탭을 옮기면 폴링이 자동으로 멈추지만, 확실하게 하려면 **[연결 끊기]** 를 누른다.

## 화면 순서 = 하는 일의 순서

```
① 보드 연결
② 보드에 담긴 레이아웃    ← 키보드 → SLOT 트리. 여기가 출발점이다
③ 배열 넣기 + 마법사
④ 배열 그림 / 눌린 키 / 직접 넣기
⑤ 보드에 담기
⑥ 파일로 내보내기
```

②가 맨 위인 이유는, 꽂은 키보드가 **이미 담겨 있는지**를 먼저 알아야
"새로 만들지 / 있는 걸 고칠지" 가 정해지기 때문이다.

## 세 가지 흐름

### 처음 만든다

1. **[보드 연결]** — USB-A 쪽에도 배우려는 키보드를 꽂아 둔다
2. ② 에 그 키보드가 `담긴 것이 없다` 로 뜬다
3. 배열을 넣는다 — **프리셋** / **KLE json 파일 열기** / KLE **Raw data** 붙여넣기
4. **[배열 읽기]** → **[마법사 시작]** → 강조된 자리의 키를 누른다
5. 못 누르는 키는 자리를 클릭하고 이름으로 직접 넣는다
6. **[보드에 담기]** — 빈 SLOT 에 담고 그 SLOT 을 고정한다

### 담아 둔 것을 편집한다

1. **[보드 연결]** → ② 트리에서 그 SLOT 의 **[편집]**
2. 배열과 **배운 키까지 그대로** 올라온다 (범례가 좌표라 되살아난다)
3. 몇 자리 고치고 **[SLOT n 에 덮어쓰기]**
   - 원본을 남기고 변형본을 만들려면 **[새 SLOT 에 담기]**

### 변형본 사이를 오간다

② 트리에서 쓰고 싶은 SLOT 의 **[적용]**. 보드가 다시 열거되고 VIA / Vial 이 따라온다.
`●` 가 지금 적용 중인 SLOT 이다. `[자동으로]` 를 누르면 고정을 풀고 첫 번째 것으로 돌아간다.

**추가 스크립트가 필요 없다.** 이 페이지와 펌웨어만으로 끝난다.

## ★ 저장 SLOT — VIA 가 정의를 VID/PID 로 찾기 때문이다

보드는 꽂힌 키보드의 레이아웃이 몇 번 SLOT 에 담겨 있는지에 따라
PID 를 **`0x5400` + SLOT** 으로 바꿔 보고한다. 담아 둔 것이 없으면 `0x5305` 다.

- **Vial** — 정의를 장치에서 직접 읽어간다. 담기만 하면 바로 그 배열이 뜬다
- **VIA** — 정의를 VID/PID 로 찾는다. 내려받은 `layout-via.json` 을 Design 탭에
  **한 번만** 넣어 두면, 그다음부터는 꽂는 대로 VIA 가 알아서 고른다

내려받는 JSON 의 `productId` 는 고른 SLOT 에 맞춰 자동으로 채워진다.
어긋나면 VIA 가 "모르는 키보드" 로 본다 — 눈에 안 띄는 종류의 오류다.

담긴 것은 두 펌웨어 모두 같은 형식이다. **VIA 펌웨어는 내용을 쓰지 않고
머리말의 vid/pid 만 본다** (그게 SLOT 을 고르는 열쇠다).
Vial 펌웨어는 그 내용을 그대로 Vial 앱에 내준다.

### 담으면 연결이 한 번 끊긴다

PID 가 바뀌면서 보드가 스스로 재열거한다. **브라우저는 PID 가 다르면 다른
장치로 본다.** 전에 허락한 적 있는 PID 면 조용히 다시 잡히고, 처음 보는
PID 면 **[보드 연결]** 을 한 번 더 눌러야 한다. 브라우저 규칙이라 우회할 수 없다.

## ★ LZMA 없이 LZMA 를 만든다

Vial 은 정의를 **압축된 채로** 읽어가는데 브라우저에는 LZMA 인코더가 없다
(`CompressionStream` 은 deflate/gzip 뿐이다). 인코더를 벤더링하는 대신
**압축을 안 했다** — `.xz` 는 "압축 안 한 LZMA2 청크" 를 규격으로 허용한다.

| 풀사이즈 153키 정의 | |
|---|---|
| minify 원본 | 1,486 B |
| **무압축 xz** (`xz.js`) | **1,548 B** |
| 파이썬 LZMA | 556 B |
| SLOT 한 칸 | **8,144 B** |

압축률을 통째로 포기해도 세 배 가까이 남는다.
`tools/kbd_upload.py` 도 **같은 무압축 형식**으로 담는다. 형식이 갈리면 그 도구로
담은 SLOT 을 이 페이지가 못 연다.

## 파일

| | |
|---|---|
| `usage-table.js` | **생성물.** `firmware/qmk-link/tools/gen_keymap.py` 의 표에서 뽑는다 |
| `presets.js` | **생성물.** `tools/gen_presets.py` 가 만든다 |
| `app.js` | WebHID · KLE 파싱 · 마법사 · SLOT 트리 · 담기/편집/적용/지우기 · 내보내기 |
| `xz.js` | 압축하지 않는 `.xz` 를 만든다. **블록 헤더 크기 바이트는 `실제크기/4 - 1`** |

**생성물을 손으로 고치지 않는다.** 두 벌을 관리하면 반드시 어긋난다.

### 프리셋은 어디서 오나

QMK / vial-qmk 의 **레이아웃 좌표** 와, 그 레이아웃을 쓰는 **키보드의 기본 키맵**을
짝지어 뽑는다. 좌표는 정확하고 범례는 그 키보드가 실제로 쓰는 이름이다.

```bash
python3 tools/gen_presets.py > presets.js      # vial-qmk 경로가 필요하다
```

손으로 그리면 1U 폭 하나만 틀려도 마법사가 엉뚱한 자리를 가리킨다.

★ QMK 의 layout 배열 순서 = `LAYOUT()` 매크로의 인자 순서라 **순서대로 zip** 하면
맞는다. 행 단위 줄바꿈과는 무관하다 — HHKB Lite 2 는 키맵 4번째 줄이 12개인데
그 행의 자리는 13개다 (오른쪽 Shift 옆 `Fn`). 행으로 맞추려 하면 어긋난다.

★ **좌표와 키맵은 같은 매크로에서 와야 한다.**

처음에 `layouts/default/<이름>/info.json` 의 좌표에다 "그 레이아웃을 쓴다고 적힌
키보드"의 기본 키맵을 붙였는데, 그 키보드의 `LAYOUT` 은 다른 매크로였다.
키가 하나 더 많아서 **범례가 두 번째 행부터 한 칸씩 밀렸다** —
1.5U Tab 자리가 비고 TAB 이 옆칸으로 갔다. 눈으로 봐야 알아채는 오류다.

그래서 지금은 세 조건을 다 만족하는 짝만 고른다:

- `keyboard.json` 에 `LAYOUT_<이름>` 이 있고
- 기본 키맵이 **그 매크로를 그대로 부르고**
- **토큰 수 == 자리 수**

마지막 검사가 이 오류를 자동으로 잡는다.
